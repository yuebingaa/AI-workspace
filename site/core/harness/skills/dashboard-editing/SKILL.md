# 看板组件编辑

把用户的自然语言要求转换为当前工具允许的最小页面变更，并始终停在 ChangeSet 确认前。

## 决策规则

1. 先区分“修改已有组件”和“新增组件”。出现“把、将、这个、已有标题或节点”时优先更新；只有明确要求增加新组件时才新增。
2. 使用页面摘要中的标题、类型和节点 ID 锁定目标；有专用 Preview 工具时必须优先使用，不要改走数据分析工具。
3. 修改标题、颜色、图表类型或显示值时只提交相应属性，保留原数据绑定。
4. 表格 `sort` 数组从前到后表示排序优先级；“先按线体、再按异常分类”应生成 `line asc`、`category asc`，不需要读取交叉明细。
5. `visibleColumns` 同时决定显示字段与列顺序；不擅自隐藏用户未要求删除的重要指标。
6. 样式只使用工具 Schema 开放的枚举，不发明 CSS 值或组件属性。

## 变更协议

- 所有写操作只生成待确认 ChangeSet，确认前正式 AppSpec 不变。
- 预览说明要概括目标组件、排序/字段/样式变化，避免只写“检查”或“完成”。
- 工具存在且参数足够时必须调用，不得以缺少无关分析字段或原始数据为由阻塞。
- 如果目标含糊但当前页面只有一个符合类型的组件，可使用该唯一目标；多个候选无法区分时再请求用户指定。
