## 1. 改造目标与完成边界

后续独立扩展（2026-09-22）：DSH接入原说明单元，支持静态文字和本轮完整单行结果引用。3001两轮真实收费任务（11模型/10工具）完成“语义总额230→动态说明230→审阅采用→保存重开→只读结论”，全量回归通过；非法表达式保存拒绝和取消已保留截图。复用原Schema、执行/回执和确认，不新增另一套文本引擎，也不重开M7或同时开放参数、多模型。详见[说明单元报告](../verification/dsh-text-cells-2026-09-22.md)；3000未发布。

目标是做一个以本地项目为基础、具有 Hex 类似分析流程的模块化数据工作空间，而不是复制其私有源码、云架构或品牌样式。

后续参数扩展（2026-09-22）：网站DSH接入原文本/数字/日期/单选参数，经单行value表输入本地SQL/Python；不增加远端参数绑定或语义筛选语法。参数-only输出不能冒充业务分析结果，原确认、来源权限与CSV试点保持。源码、实际验收与未验证项见[参数记录](../verification/dsh-parameters-2026-09-22.md)；不将此扩展解释为重新打开M7或已发布3000。

参数问答补齐（2026-09-22）：有限的“当前参数值/类型/选项”问句走同版本完整定义检索，无需运行Notebook；业务计算/修改任务不降级。目标精确定位、长值真实分页与证据保护属于本次限定范围，验证见[记录](../verification/dsh-parameter-inspection-2026-09-22.md)。不扩大里程碑、工具预算或参数类型，未发布3000。

首轮产品闭环：

```text
本地项目与文件 → 数据目录 / 授权上下文 → 手工或 AI 编辑 Cells
             → 校验依赖并执行 SQL / Python / 转换
             → 可追溯的结果 → 表格 / 图表 / 文本
             → 用户确认采用 → 看板快照 → 保存、重开、继续分析
```

这张图是产品运行流程，不是源码依赖方向。源码边界见第 4 节。

保留现有 React / TypeScript、Next 路由约定及 vinext/Vite 运行方式；保留本地项目库、现有 Harness、DuckDB 与 Pyodide 适配、已有连接驱动、ChangeSet 和确认机制。先完成本地模式，不以配置外部数据库或购买服务作为验收前提。

首轮完成到 M7 为止；后续候选项单独列出，不在实施过程中无限追加。M1 是可靠性修复，M2 是以兼容为前提的重构，M3–M6 包含明确的新产品行为，不能把它们全部称为“功能不变的重构”。后续开发按里程碑逐个落地，不做全仓搬迁。

优先收敛的故障线索：

- 工具目录的 Schema 精简会移除部分约束，而执行端继续严格验证。必须核对 `createAnalysisPlan` 等工具的生成契约与执行契约，不能只让模型反复重试，也不能删除执行端校验来“修好”。
- [任务日志](../../../TASK-LOG.md) 最近的 Python 诊断记录了外层工具预算与环境准备、实际计算预算不匹配，以及生成代码的空值 / 重复计数口径问题。本轮未复现实验；它们是 M1 的复现输入，不是本轮新增验证成果。
- 当前有增量编辑 Cells 的工具路径，也有计划到 Notebook 草稿的路径。需要继续收敛，不能把“每次都重新生成整个 Notebook”当作默认交互。
- 手工执行与 Agent 获取原始工作簿的路径、生命周期不同。不能因为 Context 列出了文件名，就认为 Agent 已获准读取其内容。

### M1：先修稳真实分析链路

主要入口：`core/harness/tool-registry.ts`、`tool-schema.ts`、`analysis-plan-contracts.ts`、`runtime.ts`、`core/notebook/server/python-runtime.ts`、Notebook 执行器及相关测试。

1. 从同一个业务 Schema 生成工具描述并在执行端校验；供应商不支持的 Schema 关键字采用明确的适配和补充约束说明，不静默丢失规则。保留字段路径、期望类型 / 上限等结构化错误，禁止在错误中回显敏感输入。
2. 为已知的字段名、依赖数组与 `cellSearch` 参数失败建立离线回归。无效参数不触发执行副作用；只有可修复错误进入有次数上限的纠正流程。
3. 分开记录模型等待、运行环境准备、实际计算、结果转换。制定有上限且相互协调的 Notebook 工具预算；继续支持用户取消，不将“取消配额”解释为无限计算或无限重试。
4. 让失败时可查看草稿代码、失败阶段和安全错误说明，但不自动采用草稿、不输出敏感原始行。第二批采用当前窗口的有界只读诊断，不持久化、不自动进入下一轮模型上下文；取消 / 撤权不回传代码，无有效运行回执明确标为未知。实际验证与截图见[第二批记录](../verification/hex-notebook-diagnostics-2026-09-16.md)。持久化失败草稿需另行复用项目范围与现有隐私规则，尚未实施。
5. 对“重复行是否计第一次”“纯空格是否为空”等口径使用显式定义和确定性样例；生成代码的结果必须与预期核对，不能仅以执行成功为准。第三批将当前 Dataset 与原件解析范围分开，详情和已有工具共用纯统计，普通 / 压缩上下文不丢失相关统计规则；固定 CSV 及独立 SQL / Python 结果、失败 / 取消和截图见[第三批记录](../verification/hex-dataset-quality-2026-09-16.md)。这不等于任意模型生成代码已获得通用语义正确性验证；该项和完整原文件质量检查继续保留为后续边界。

验收：离线模型替身驱动真实工具链，合法计划通过、非法计划准确报错；冷 / 热环境都能区分准备与计算耗时；取消不继续执行后续工具；合成数据计数正确。模型质量实测只能在另有明确授权与费用边界时进行，未做时写“真实模型端到端未验证”。

## 5. 如何保证以后可以增加、关闭和删除功能

### 增加一个功能

以未来新增 Pivot Cell 为例：增加配置 Schema / 稳定类型、依赖声明、对应计算处理器、编辑器、结果展示与测试，再接入浏览器和服务端各自的注册表。只有实际存在数据聚合差异时才扩展业务用例；不为一个 Cell 修改模型供应商 HTTP、Harness 循环或项目保存队列。Pivot 本身不属于首轮必须交付的功能。

允许少量有意义的中心修改，例如扩展类型联合、Schema 或注册表；目标是减少联动，不承诺任何功能“只加一个文件、完全零改动”。共享目录只放稳定描述，不把服务端实现通过统一 `index.ts` 导出到前端。

### 关闭与移除分开处理

1. **关闭入口**：能力目录同时控制 UI 可创建类型、Agent 可用工具 / 能力描述、服务端执行许可；只隐藏按钮不算关闭。能力开关不能替代授权检查。
2. **保留项目**：已保存的禁用类型显示只读占位、原配置和依赖说明，不执行；恢复能力后可继续使用。其下游标记阻塞，不偷偷换算法。
3. **兼容未知类型**：项目读入层可以安全保存带版本的原始定义，执行层仍严格验证已支持类型；“可打开”不等于“允许执行任意内容”。未知类型不能导致整份项目被自动清空或重写。
4. **真正移除代码**：先检查类型、注册、动态加载、API、数据依赖和旧项目；有迁移需要就提供备份和显式迁移。无法安全迁移时保留小的只读兼容器，不删除数据。
5. **移除验证**：测试该能力缺席时其他功能继续可用，客户端 bundle 不拉入对应服务端依赖；检查旧项目能打开，API 明确返回不支持而非 500。

Python 已实现部署级关闭、定义保留、三层执行阻断与恢复，并通过第九包支持不携带离线资源的独立产物。当前站没有执行物理卸载；Python 类型 / 适配代码和共用依赖仍保留，不代表任意模块已能删除。项目仍不具备完整未知 Cell 兼容加载；不得以放宽所有 Zod 校验来替代分层的读取与执行校验。

### 将来替换具体实现的主要位置

| 替换项 | 主要修改位置 | 必须保留或明确的差异 |
| --- | --- | --- |
| 模型供应商 | `core/ai/server/` 新适配 + `harness-composition.ts`；遵守 `HarnessModel` | 工具调用、图片、流式输出、取消与用量能力；缺失能力明确拒绝或走已声明路径 |
| 外部数据库 | `core/connections/server/drivers/`、驱动选择 / 配置适配 | 方言、类型、认证、取消、分页、只读权限；不将数据库权限复制到模型提示词 |
| 本地 Python / SQL 引擎 | `NotebookExecutionDependencies` 的实现与 `server/runtime.ts` 组装 | 环境准备、包能力、时间 / 内存、数据类型、结果完整性和取消 |
| Agent 策略 | `core/harness/` 中规划 / 路由模块及对应组装 | Tool 名称与参数兼容、验证证据、草稿确认，不直接更改执行器或数据库 |
| 图表库 | M5 的 renderer 适配及其配置映射 | 交互、坐标、聚合、空值和图表能力可能不同，不能承诺换库后像素完全相同 |
| 项目 / Dataset 存储 | 各自仓库端口的具体适配与组装 | 版本冲突、迁移、删除 / 回收语义；不在 React 组件中替换文件系统代码 |

## 6. 状态与数据所有权

| 状态 | 所有者与生命周期 | 明确禁止 |
| --- | --- | --- |
| Notebook / 语义定义、页面布局 | 项目状态与版本化保存入口；只有确认的变更进入正式状态 | Tool、UI 和执行器分别维护互不一致的正式文档 |
| 导入文件、Dataset、数据目录 | 项目文件 / Dataset 仓库及授权元数据适配 | 用文件名称冒充权限；删除 Dataset 时无提示地销毁原文件 |
| 单次运行、取消、结果证据 | Notebook 执行与结果访问；区分临时结果和显式保存的数据 | 把上次成功结果当作这次失败任务的输出 |
| AI 草稿与任务状态 | Harness 任务 / 草稿机制，带基础修订和运行身份 | 绕过用户采用，或用旧草稿覆盖较新的项目 |
| 聊天历史、摘要、工作记忆 | 现有会话存储，按项目 / 会话隔离 | 因 UI 显示历史，就假设模型已收到或有权读取全部文件 |
| 选中对象、展开、宽度、编辑中输入 | UI 局部状态；需要恢复的部分经明确项目适配 | 将组件引用、浏览器对象或服务器凭据写入项目文件 |

任何结果缓存即使第一版只有本地用户，也必须携带项目与访问范围；人工和 AI 的结果策略不一定相同。复用公共执行能力，不等于合并两类权限或掩码行为。
