## 实际完成的职责拆分

### 模型与 Harness

- `HarnessRuntime` 只使用 `HarnessModel` 及工具/验证能力，不再导入 DeepSeek 模型实现。`CoordinatedHarness` 也不自行创建供应商客户端，仍保持原单 Agent 默认路径和受开关限制的数据角色。
- DeepSeek 三类请求的 HTTP 构造、响应 Schema、模型标识、Token 用量及动作解析移至 `core/ai/server/deepseek-harness-model.ts`，没有重写提示、变更温度或请求参数。请求地址和响应字节限制由 `deepseek-endpoint.ts` 统一提供，不再通过旧 ChangeSet Planner 导入常量。
- `harness-composition.ts` 收拢配置选择，返回惰性 `createModelClient`。密钥与供应商配置留在服务端闭包，不进入执行器选项或模型上下文。显式 `modelClient` 优先，构造时序及未配置错误保持原样。
- `model-policy.ts` 维护原有路由/规划提示及限制，保证执行前的输入估算和适配器使用同一文本；`model-errors.ts` 维护通用致命协议错误和携带用量的格式错误。
- `deepseek-harness.ts` 保留旧构造方式、常量及错误导出，只委托给唯一执行实现。SSE 路由测试的 spy 改到真实 `HarnessRuntime`，原验证断言保留。

### SQL 与数据库

- `query-service.ts` 通过 `ConnectionQueryDependencies` / `ConnectionDriver` 工作，负责 SQL 提前校验、授权配置解析、两并发额度、12 秒取消信号、返回前撤权复查及错误脱敏。
- `drivers/postgres.ts` 保留 `BEGIN READ ONLY`、数据库超时、逐行字节限制、连接销毁及文本类型解析；`drivers/databricks.ts` 保留 Statement 提交/轮询、同源受控结果、分块不完整标记及独立有界取消请求。Schema SQL 由各驱动生成。
- `result-table.ts` 统一两驱动共有的字段/行/字节校验和标量映射；保持空值、日期/时区文本、BIGINT / DECIMAL 精确字符串及截断标记，不增加隐式精度转换。
- `configuration.ts` 是无 IO 的配置定义；`server/config.ts` 继续负责环境读取、公开描述符和项目/Agent 授权。`server/query.ts` 只组装一个共享服务，API、Notebook 和 Agent 的并发额度不分裂。

### 浏览器边界

`core/http/bounded-body.ts` 是唯一的共享 Web Streams 实现；六个客户端只改 import。原 `server/bounded-body.ts` 保留原名重导出，新增测试证明函数和 `BoundedBodyError` 类身份完全相同。没有改二进制读取器，也没有将 Node、数据库或密钥代码移到前端。
