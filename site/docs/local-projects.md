# 本地项目与 Data Browser

实现状态：2026-09-13 第一版本地模式已在开发站 `http://127.0.0.1:3001` 完成浏览器验收；未自动发布到稳定站或重新打包便携版。

## 使用方式

1. 左侧点击 **Data Browser**（收起侧栏时也有数据浏览器按钮）。
2. 在“项目文件夹”中新建空白项目，或输入已有 AgentCanvas 项目的绝对路径打开。新建时路径留空，使用用户“文档 / AgentCanvas Projects”下的新目录。
3. 在该项目中导入 CSV / XLSX。选择的工作表成为独立数据表，原始文件另行保留；相同 XLSX 的多个工作表关联同一原件。
4. 数据表可预览字段和记录、供 Notebook 使用，或加入 AI 上下文。语义模型沿用现有创建、选择、编辑、删除界面，并随项目保存。
5. Notebook 的“生成看板预览”会重新运行并把结果快照保存为项目结果表；审阅来源单元、版本、运行标识和行列数后，点击“确认加入看板”才修改正式看板。表格最多 30 列 / 500 行，请先选择列或聚合；更宽的完整结果仍可保存为数据集。
6. 等待顶部显示“已保存到本地项目”再关闭。重新打开项目可恢复定义和数据。切换回临时工作区不会清除原有浏览器工作区。

第一版输入文件夹路径，不提供操作系统文件夹选择器；不能把已有的任意非空文件夹直接当作项目。先创建空白项目，再导入文件。文件访问发生在运行网站的本机服务端，不是远程网页任意扫描访问者电脑。

## 文件夹结构

```text
我的项目/
  agentcanvas.project.json   项目清单、稳定 ID、原件关联、工作台定义与保存版本
  files/
    file-<UUID>.xlsx         原始文件（也可以是 CSV）
  tables/
    table-<UUID>.json        有类型的字段、数据行、数据质量和访问策略
```

清单中的文件位置为相对路径。数据表重命名不改变 ID。工作台定义包括 Notebook DAG、DataRecipe、语义模型及选择、AppSpec、ChangeSet 历史、最近聊天和任务记录；不等于保存整个服务端长期会话库。原始 XLSX 在 Data Browser 中可下载，刷新后不会自动恢复旧侧栏的浏览器 File 对象。

聊天顶部的会话下拉只列出当前项目，右侧“＋”开启新会话。消息、文字草稿和当前选择随项目保存，旧聊天自动成为第一条会话；每项目最多 50 条会话，每条保留最近 20 轮。清除上下文只作用于当前会话，其他会话和任务审计保留；运行或变更预览期间暂停切换。图片草稿仅保留在当前窗口，不写入项目。工作台快照现为 v6，兼容迁移 v5 及更早版本；JSON 备份包含会话列表，恢复时重新建立服务端上下文，不混入备份之后的服务端消息。

Notebook 单元的临时运行缓存不在项目清单中：重新打开后需重跑；显式生成的结果快照才是持久结果。结果仍遵守现有行数、字段、超时和敏感数据处理限制。尚未提供项目库独立的 SQL/Python 编辑器、数据库文件管理器或多人协作。

看板使用固定结果快照：修改、删除或重跑 Notebook 不会自动更新已加入的图表 / 表格。待确认快照的来源步骤变化时会提示历史版本；需要最新结果请取消并重新生成。取消预览或撤销加入操作不会删除已保存的结果表，来源仍可在 Data Browser 查看。未确认预览关闭后不自动恢复应用；已确认看板、撤销历史和审计随项目保存。快照生成与看板状态保存不是一个事务，操作失败后也不要自行清理项目文件。未打开本地项目时仍按临时数据保留期保存，不承诺永久可用。

## 保存、冲突和恢复

- 数据文件为唯一名称、不覆盖的快照；清单采用有大小上限的原子写入、写入锁及内容比较。
- 工作台定义按 `stateRevision` 乐观并发检查。同项目多窗口写入发生冲突时暂停自动保存，不以最后一个窗口强行覆盖。关闭面板后先用顶部“备份”导出未保存定义，再在 Data Browser 中明确选择放弃未保存修改、重新打开磁盘版本。
- 保存暂时失败时，当前修改仍保留在窗口，可打开 Data Browser 点击“重试保存”。系统先读取同一项目的磁盘版本：没有其他修改才继续保存；上次已经写入但成功回执丢失时确认原写入，不重复保存。核对期间的后续编辑仍会保留。真实版本冲突不会被重试强行覆盖，仍可先导出备份再确认放弃并重新打开。重试为手动操作，没有后台无限重试。
- 当前窗口存在未确认的看板预览时，切换/退出项目会先询问是否放弃预览；不会把预览自动写成正式看板。数据目录也会保护该窗口正在预览引用的数据。
- 顶部 JSON “备份”只含工作台定义，不包含全部原件和数据行。完整备份应等待保存完成，再复制整个项目文件夹；不要在正在导入/保存时复制。
- 项目移动或复制后，使用新路径“打开已有项目”；不要只复制清单。另一台电脑仍需要可用的 AgentCanvas 本机程序，项目文件夹不是运行程序。
- 删除数据表会移入回收站，保留文件和 ID，可恢复。Notebook、语义模型、正式看板、可撤销历史或处理配方仍有引用时拒绝删除；第一版不提供永久清空或自动清理。
- 删除 Notebook 步骤前会列出本步骤和明确引用它的全部直接 / 间接下游，确认后一起移除这些步骤，原数据、模型及已保存看板 / 结果快照保留。审阅打开后只要文档定义变化，旧确认就失效，需关闭后重新查看；运行或编辑期间不能确认。步骤没有回收站，如需恢复请保留删除前的备份。只识别结构化输入及文本引用，不扫描自由代码。详见 [M6 第六包](verification/hex-cell-deletion-impact-2026-09-21.md)。
- 删除语义模型前，管理弹窗展示所有工作界面 Notebook 的引用位置；仍被语义查询单元引用时禁止删除，请先明确修改或删除对应单元。无引用模型仍需确认，仅移除模型和选择状态，不删除表格、看板或历史结果。模型没有独立回收站；如需恢复定义，请保留项目备份。未采用的旧 AI 草稿不会一直阻止删除，但模型不在当前界面时不能再采用该草稿，需要重新生成。项目保存还会复查本次被移除模型的引用，失败不会覆盖清单。
- 原始文件行的垃圾桶按钮将原件移入回收站，已导入的数据表、Notebook 和看板继续保留；没有可用关联表的原件也能归档。可从文件栏底部进入回收站恢复文件，恢复前检查原件完整性；重新导入相同文件也会恢复原件。归档不释放磁盘空间，仍计入文件数和容量限制。临时会话的“移除”只释放当前窗口原件，再次读取完整工作簿需重新导入。
- 删除原件前，两处文件入口均展示当前所有 Notebook 中显式按文件名读取它的 Python 步骤和各自下游数量；有引用时需勾选了解重跑风险。未发现引用不等于自由代码或未采用草稿均无影响。数据表和定义保留，但读取原件的 Python 及下游可能无法再次运行；已有结果不会自动重新计算，从回收站恢复后需手动重跑。引用区分文件名大小写而非绑定文件 ID，本次上传同名文件优先、项目内多份有效同名原件拒绝读取；移除其中一份可能改变唯一候选。详见 [M6 第五包](verification/hex-file-deletion-impact-2026-09-21.md)。
- 写入中断极少数情况下可能留下未登记的快照文件；不会主动删除它们。不要自行编辑清单或清理看起来重复的文件。

## 文件缺失或损坏时

- 若显示“项目定义与当前版本不兼容”，先保留整个项目文件夹。当前版本会拒绝读取 / 保存未知 Cell、较新工作台版本或不支持的 AgentCanvas 格式，而不是丢弃未知定义或替换为空白；提示只列出有界的位置及类型，不展示未知源码。请使用兼容版本，或在确认备份完整后恢复正确项目文件，再显式重试打开 / 保存。这个提示不是文件已修复或项目可只读打开的证明。
- 已打开的旧窗口遇到磁盘定义不兼容时同样暂停保存，当前未保存编辑仍在窗口；不要关闭窗口前忘记备份。上次项目恢复失败时会明确回到临时工作区，临时编辑不会自动写入拒绝打开的项目。

- Data Browser 的目录来自项目清单，不等于已经逐个核验文件；读取、下载或恢复时才检查实际内容。
- 错误会给出项目内相对位置，例如 `tables/table-<UUID>.json` 或 `files/file-<UUID>.csv`。请先停止外部修改并保留当前项目，再从可信的完整项目备份核对并恢复对应文件；缺失目录不要用空目录代替丢失内容。没有完整备份时，程序不会猜测修复或删除引用。
- 原始文件和已导入数据表分别存储。只丢失原件时，该数据表仍可读取；丢失表快照时，原件不会被自动重新解析为原数据 ID。重新导入会产生新 ID，需要显式检查与调整旧分析绑定，不能当作原引用已修复。
- 回收站恢复先校验实际字节、摘要及表格式。缺失或损坏时保持在回收站，项目清单不因失败而改写；恢复了正确备份后可再试，成功保留原 ID。
- 错误仅定位问题，不提供自动恢复、全项目扫描或定期健康检查；读取期间的检查也不是对未来文件状态的保证。

## 容量和数据边界

每项目最多 50 张表（含回收站）、100 份原件；原件不超过 10 MiB、单张有类型数据快照 32 MiB、登记数据总量 512 MiB、清单 8 MiB。已有 CSV、Notebook 和备份大小上限仍分别生效。适合本地小型分析项目，不是大数据存储系统。

项目数据不受临时数据的 30 分钟 TTL 影响。未打开项目时仍使用原来的临时仓库和过期规则。临时数据不能仅靠设置 `storageMode` 绕过过期限制。

仅本机回环地址与同源页面可使用项目 API。请求使用服务端登记的随机项目句柄，数据、Notebook、Harness 和会话都按项目范围选择；无句柄的请求走临时模式。不支持 UNC、磁盘根目录、用户主目录、符号链接或目录联接，读取文件会检查类型、大小和 SHA-256。

这是本地单用户模式，没有实现登录、多用户文件权限或加密。可信本机进程仍可访问用户拥有的文件；同源安全检查不是操作系统安全沙箱。模型 API Key、数据库凭据及运行环境配置不写入项目清单，仍由服务端私有运行目录管理；导入的文件和聊天文本本身可能包含敏感信息，项目文件夹应视为私有，不能直接提交 Git 或公开分享。

`local-projects.json` 仅在 `STUDIO_LOCAL_STATE_DIR` 中登记最近项目路径与句柄；目录索引最多 1,000 个、文件最多 5 MiB，由服务端统一限制。已满时明确拒绝新增，不自动淘汰原记录；已有项目仍可重新打开。通过 `npm run site:*` 管理的本机站点已配置该目录。目录登记文件不是项目正文，搬家时无需复制它；在另一台机器重新打开项目即可登记。

## 验证

新增单元测试覆盖重开与目录复制、数据完整性、访问策略、引用保护、回收站和版本冲突；浏览器验收脚本与本轮实测结果见 [Agent 架构维护入口](architecture/agent-architecture.md)。测试数据均为合成数据，不读取内部 Excel 或真实数据库。
