# 语义模型（单表第一版）

语义模型把原表字段转换成可复用的业务维度和固定指标口径。它不是大语言模型配置，也不是一段任意执行的 SQL。

## 使用

1. 在当前工作界面导入 CSV 或 Excel 表格。
2. 左侧「语义模型 → 创建」，设置模型名称、来源表及业务说明。
3. 添加维度（例如「销售区域 → region」）和至少一个指标（例如「销售额 → amount 求和」）。业务名称可用中文；标识使用英文字母开头的字母、数字、下划线。
4. 点击「预览计算」核对真实表格结果，再「保存并选择」。
5. 在侧边栏选择模型，或在 AI 工作台「添加上下文 → 选择语义模型」选择。选择同时切换到模型的来源表，然后可提问「按销售区域统计销售额」。
6. 模型旁的「···」打开管理器，可以编辑、预览或删除。删除会再次确认；不会删除原表、已有图表或历史结果。

支持求和、平均值、计数、去重计数、最小值、最大值；可用计算方式以字段支持能力为准。空值沿用 DataRecipe 的严格校验规则（包括计数），不会暗中填零或按 SQL 的忽略 NULL 规则计算；需先清洗数据。

## 保存与范围

- 模型保存在现有浏览器工作区内，随工作区备份一起导出/恢复。旧备份不含语义层时仍可打开。不要把 API Key、密码或敏感原始记录写入说明。
- 模型按来源数据表的工作界面归属展示，各界面各自记住选择；选择不同的数据表时，不向 AI 携带不匹配的旧模型。
- 编辑保持模型 ID，版本递增。新定义作用于后续任务；不会自动重写已有图表和历史分析。模型删除不撤回已生成内容。
- 删除工作界面时，原有数据迁移规则不变；模型跟随原表保留，失效界面选择被清理。被模型引用的表格需要先删除模型或重新绑定后才能删除。
- 临时上传数据的有效期不变。保留模型定义不代表原始数据永久保存；数据过期后需要重新导入并编辑模型重新绑定。
- 查看者可查看和选择模型，不能创建、编辑或删除。AI 任务执行期间禁止修改/切换模型，防止本轮计算口径变化。

## AI 集成与边界

选中模型后，其定义、版本与来源表进入请求和会话选择上下文。`querySemanticModel` 按需出现在 Tool Registry，只接受已定义的维度/指标标识，编译成受控 DataRecipe 在服务端计算。服务端仍检查数据归属、上传有效期和敏感字段授权；业务说明不构成指令或权限。

结果输出到现有表格结果区，Evidence Bus 记录模型 ID、版本和来源表。Planner 将语义查询纳入数据任务，Verifier 要求对应版本的查询证据。AI 新增/更改数据绑定必须遵守所选模型的字段与聚合口径，页面变更仍只生成 ChangeSet 预览，用户确认后才应用。编辑已有组件的样式不改写其原有绑定。

敏感性按原表字段追溯，不会因业务别名而丢失。AI 查询结果和任务表格中的敏感维度使用匿名分组；敏感字段的非计数指标隐藏为 `null` 并标明隐藏字段。计数、去重计数仍可用于分析，原表不改写。管理器的本地计算预览仅供用户核对，不作为模型输入。

第一版每个工作区文档最多 30 个模型，每模型最多 20 个维度和 20 个指标；一次查询最多 5 个维度、20 个指标和 100 行结果，管理器预览最多 10 行。返回截断结果会标明限制，不能作为全量明细。

本版不包含跨表 Join、计算表达式、任意 SQL、外部语义层同步或语义结果直接导出 Excel。需要这些能力时应扩展专门的查询编译和权限边界；不要绕过模型把另一份普通配方的导出称为语义结果。

## 验证

在 `site/` 执行 `npm test`、`npm run typecheck`。`node scripts/verify-semantic-models.mjs` 在 3001 使用隔离 Edge 和合成 CSV，核验创建、计算预览、选择、刷新保存、版本更新、工作界面隔离、删除确认和窄屏渲染；截图与报告写入 `.runtime/semantic-models/`。该脚本拦截 AI 请求，不调用外部模型，不读取用户浏览器工作区，不发布到 3000。
