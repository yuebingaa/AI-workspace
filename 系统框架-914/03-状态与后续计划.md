## 2. 运行开关与入口

以下列出配置含义，不记录任何私有配置值或密钥；本次没有核查运行进程是否实际开启了 `data` 或外部 MCP。

| 配置 / 入口 | 当前含义 |
| --- | --- |
| `HARNESS_MULTI_AGENT_MODE=single\|data` | 源码默认 single；data 只对满足条件的首轮任务尝试委派 |
| `HARNESS_MAX_MODEL_CALLS` / `HARNESS_MAX_TOOL_CALLS` | 服务端调用额度；任务类型可能进一步收紧 |
| `HARNESS_MODEL_REQUEST_TIMEOUT_MS` / `HARNESS_TOOL_CALL_TIMEOUT_MS` / `HARNESS_TOTAL_EXECUTION_TIMEOUT_MS` | 单次模型、工具及总截止时间 |
| `HARNESS_MAX_TOTAL_INPUT_CHARS` / `HARNESS_MAX_TOTAL_PROMPT_TOKENS` | 总上下文预算；仍受实现硬上限约束 |
| `HARNESS_VISUAL_VERIFICATION_ENABLED` | 工作台可选截图/多模态验证；需配置视觉提供方和截图服务 |
| `HARNESS_MCP_ENABLED` / `HARNESS_MCP_ALLOW_STDIO` | 外部 MCP 总开关与 stdio 显式允许项 |
| `STUDIO_LOCAL_STATE_DIR` | 私有本地状态与项目登记等持久化入口 |
| `/api/ai/harness` / `/api/ai/harness/stream` | 工作台 JSON / SSE 请求，共用 handler |
| `/api/ai/visualization-lab/stream` | 固定合成数据的独立可视化测试，始终单 Agent |

模型经 API 设置选择的运行时值保留在进程内；环境配置是另一来源。9/13 测试曾通过重新检测模型列表解决模型名不一致，不能将该临时选择当成环境文件已经更新。

## 5. 后续建议顺序

以下是建议，不是本次新增实现或已承诺排期。

1. **先修复真实任务暴露的问题。** 针对复杂 Notebook 输入预算、数据任务工具选择、看板标签和图表边缘裁切，固定用例并保留失败/成功证据；不能只用手动计算替代 Agent 生成。
2. **完成一个可视化子 Agent 的闭环。** 定义一个 visualization 角色、受限工具、独立上下文、候选渲染与结构化回传，先覆盖现有折线图；使用当前测试页验收数值与人工视觉结论。
3. **把专项 Skill 和绘图工具配齐。** 选型与渲染适配分别推进，热力图、时间播放、筛选联动各自定义验收；Vega-Lite/Flint/VegaFusion 是研究候选，不能当作现有依赖。
4. **统一产物引用与依赖传递。** 明确版本、授权、生命周期、摘要上限和按需读取，避免将子任务全量结果重新灌入主上下文。
5. **有评测证据后再扩大多 Agent。** 同任务比较单/多 Agent 的正确率、费用和时延，再决定并行、失败重新委派与默认启用范围。
6. **单独验收与发布。** 真实远端数据库、企业接入、稳定站部署和便携包更新各自安排，不把源码归档当成完成发布。
